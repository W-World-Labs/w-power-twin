# W Power Twin public source

This is the complete educational synthetic plant-twin application: Rust catalog validation, thermal/wind/PV/CSP simulation, fault-feature rules and the bilingual React/Three.js interface. Preserve the owning implementations and every existing assertion. Do not reduce this distribution to SDK wrappers or add unnecessary unit/integration tests.

Use small, direct changes. Frontend changes consult modern-web-guidance first and target Baseline Widely available browsers. Local work is source editing, metadata review and privacy scanning only; dependency installation, original tests and builds run on standard GitHub-hosted runners in PUBLIC repositories.

The catalogs contain illustrative equipment, KKS-style labels, positions and capacities, not customer plant records. Synthetic output is not a real plant feed, engineering certification, IAPWS-IF97 solver or media inference result. Never operate plant equipment, production services or customer accounts during source validation.

No downloaded model, HDRI, texture, dataset, aerial reference, asset lock, credentials, deployment binding or private history is included. Preserve data/sources.json attribution/review metadata and optional loaders; its licence fields record upstream declarations, not a new redistribution grant. Research datasets default to fetch=false. Only an explicit operator action after reviewing current rights may obtain external assets; CI must never fetch them. Existing 3D views require the external assets described in README.md.

Default operation has no telemetry. Backend capture requires operator-supplied W_RADAR_CODE and W_RADAR_ENDPOINT; browser telemetry requires a separate explicit build opt-in and non-secret public fields. Never put operator API keys in browser variables. Keep public dependency revisions immutable.

The public workflow checks existing Rust assertions and frontend compilation, scans source/history/all Git objects and uploads only exact source plus licence-declaration inventories and checksums. Compiled frontend/backend files and dependency implementations stay in the runner. Keep source-provenance.json synchronized with every tracked file except itself. A source CI result does not establish browser/assets, actual media models, field devices or production acceptance.
